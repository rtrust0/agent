# 辰光 Agent 平台 · RBAC 权限中心 UI 原型设计说明书

> 对应需求文档：`docs/spec/PROJECT_SPEC_V2.md`（RBAC 授权功能增强版）
> 产物目录：`docs/ui/rbac/`
> 本文档：`docs/design/ui/RBAC-UI-设计说明书.md`

---

## 一、概述

本原型用于演示辰光 Agent 平台 **RBAC 授权功能**的前端交互形态，核心是"**谁能访问什么、能做什么**"的权限控制体验。原型聚焦三个维度，与 `PROJECT_SPEC_V2.md` 第三章的前端需求一一对应：

1. **侧边栏菜单按权限显示/隐藏**（对应 3.2）
2. **操作按钮按权限显示/隐藏**（对应 3.3）
3. **路由守卫的无权访问拦截**（对应 3.4，以 403 页呈现）

原型的标志性交互是一个**身份切换器**：顶栏可在「超级管理员 / 运营管理员 / 只读观察者」三种身份间一键切换，切换后菜单项、操作按钮即时增删，直观呈现权限差异——这正是 V2 需求的验收标准第 4、5、7 条的 UI 落地。

---

## 二、设计目标

| 目标 | 说明 |
|---|---|
| 演示权限差异 | 同一套界面在不同身份下呈现不同可见性，让授权逻辑"看得见" |
| 表达权限矩阵 | 把 `模块:操作` 权限码与角色之间的授权关系做成可视化矩阵 |
| 企业级质感 | 面向系统管理员/运维的产品，追求精确、克制、可审计的视觉气质 |
| 可落地 | 视觉与交互均可直接映射到现有 React + shadcn/ui 技术栈实现 |

## 三、视觉设计系统

### 3.1 设计主题：权限蓝图（Permission Blueprint）

"辰光"是黎明之光，RBAC 是关于访问边界的系统。设计将两者结合：**深海蓝（黎明前的天）作主结构，曙光金作品牌强调**，用工程蓝图的精确网格语言表达"可审计的访问控制"。

全站最独特的一件东西是**权限矩阵**（权限管理页）：以"权限项 × 角色"的二维网格呈现授权关系，勾选状态即授权状态。矩阵既是信息本体，也是贯穿全站的视觉母题。

### 3.2 色彩

| Token | 值 | 用途 |
|---|---|---|

| `--navy-800` | `#16243B` | 登录页验证码底色 |
| `--ink` | `#18212E` | 主文字 |
| `--ink-2` | `#5A6675` | 次级文字 |
| `--ink-3` | `#8B95A3` | 弱化文字、占位 |

| `--panel` | `#FFFFFF` | 面板 |
| `--brand` | `#3E63DD` | 主交互色（靛蓝，主按钮/激活态） |
| `--dawn` | `#E2A13C` | 品牌强调（曙光金，内置角色/警示） |
| `--grant` | `#1E7A5A` | 授权绿（已授权勾选/成功/活跃） |
| `--danger` | `#C2453C` | 警示红（删除/停用/拒绝） |

### 3.3 字体

| 用途 | 字体 | 说明 |
|---|---|---|
| 拉丁标题与数字 | Space Grotesk | 工程感，有辨识度，通过 Google Fonts 引入 |
| 权限码 / ID / 数据 | IBM Plex Mono | 等宽字体，权限码 `user:create` 的内容天然需要 |
| 中文正文 | PingFang SC / Microsoft YaHei / Noto Sans SC | 系统字体栈 |

字阶：页面标题 22px、面板标题 14px、正文 13.5px、辅助 12.5px、徽章 11.5px。

- 内容一律左对齐；卡片用细边框（`1px solid var(--line)`）+ 极轻阴影，不做统一大圆角。

### 3.5 图标

原型不依赖外部图标库，所有图标以**内联 SVG** 形式内置在 `js/app.js` 的 `ICONS` 对象中（24×24、2px 描边、round 线帽），风格统一，正式实现时可替换为 lucide-react。

## 四、页面清单与结构

| 文件 | 页面 | 核心演示点 |
|---|---|---|
| `login.html` | 登录 | 用户名/密码 + 图形验证码（4 位随机字符，点击刷新） |
| `index.html` | 工作台 | RBAC 概览：统计卡片、当前身份权限清单、矩阵预览 |
| `users.html` | 用户管理 | 添加用户、分配角色、删除；按钮权限差异 |
| `roles.html` | 角色管理 | 创建角色、分配权限、编辑、删除；按钮权限差异 |
| `permissions.html` | 权限管理 | **权限矩阵**（核心特色）、创建权限 |
| `403.html` | 无权访问 | 路由守卫拦截的无权提示页 |

### 4.1 侧边栏结构

- 平台组：工作台（无权限要求，恒显示）
- 系统管理组：用户管理、角色管理、权限管理、API 密钥、审计日志、告警规则、系统配置
- 每个系统管理菜单项绑定一个权限码（见下表），无权限即不渲染；若全部子项无权限，则"系统管理"父菜单整体消失（符合 V2 3.2 控制逻辑）。

| 菜单项 | 权限码 |
|---|---|
| 用户管理 | `user:list` |
| 角色管理 | `role:list` |
| 权限管理 | `permission:list` |
| API 密钥 | `system:api_keys` |
| 审计日志 | `system:audit` |
| 告警规则 | `system:alerts` |
| 系统配置 | `system:settings` |

### 4.2 按钮权限映射（与 V2 3.3 一致）

| 页面 | 按钮 | 权限码 |
|---|---|---|
| 用户管理 | 添加用户 | `user:create` |
| 用户管理 | 分配角色 | `user:assign_roles` |
| 用户管理 | 删除用户 | `user:delete` |
| 角色管理 | 创建角色 | `role:create` |
| 角色管理 | 编辑角色 | `role:update` |
| 角色管理 | 分配权限 | `role:assign_permissions` |
| 角色管理 | 删除角色 | `role:delete` |
| 权限管理 | 创建权限 | `permission:create` |

实现方式：每个按钮带 `data-perm="权限码"` 属性，`applyButtonPermissions()` 遍历后为无权限按钮设置 `data-perm-hidden="true"`，由 CSS `[data-perm-hidden="true"]{display:none!important}` 隐藏。这套机制与正式实现中"无权限不渲染"语义等价。

## 五、三种演示身份

| 身份 | 角色 | 权限概要 | 可见差异 |
|---|---|---|---|
| 超级管理员 | super_admin | 全部 22 项权限（`superuser=true` 直接放行） | 所有菜单与按钮均可见 |
| 运营管理员 | ops_admin | 用户/角色的读、创建、更新；权限只读 | 看不到"删除""分配角色/权限"按钮；看不到系统配置类菜单 |
| 只读观察者 | viewer | 用户/角色/权限只读 | 看不到所有增改删按钮；系统管理仅剩三个只读页面 |

身份状态存于 `localStorage`（`chenguang.rbac.identity`），切换后整页刷新生效。

## 六、交互设计

### 6.1 身份切换器

顶栏右侧的分段控件（segmented control），三个 tab 对应三种身份。点击后写入 localStorage 并刷新，全局菜单与按钮即时重算。这是原型最核心的交互。

### 6.2 权限矩阵（permissions.html）

- 行：22 项权限，按 user / role / permission / system 四模块分组；
- 列：3 个角色；
- 交叉点：绿色实心勾 = 已授权，空心 = 未授权；
- 表头与模块行 sticky，横向滚动时保持可见。

### 6.3 弹窗

- 添加用户 / 创建角色 / 创建权限：表单校验，缺失字段给出 Toast 提示；
- 分配角色 / 分配权限：复选框列表，按模块分组；
- 删除确认：二次确认对话框，删除按钮为警示红。

### 6.4 Toast

操作结果（创建成功、权限已更新、删除完成等）通过右下角 Toast 反馈，成功为授权绿圆点，失败为警示红圆点。

### 6.5 登录验证码

4 位随机大写字符（排除易混淆的 0/O/1/I），点击验证码图片可刷新，输入不区分大小写。原型中登录成功后跳转工作台（不校验真实后端）。

### 7.1 第一套产物：静态页面（HTML + CSS + JavaScript）

```
docs/ui/rbac/
├── login.html          # 登录页
├── index.html          # 工作台（RBAC 概览）
├── users.html          # 用户管理
├── roles.html          # 角色管理

├── 403.html            # 无权访问
├── css/
│   └── style.css       # 全站样式（设计令牌 + 组件）
```

存放于 `docs/ui/rbac/screenshots/`，覆盖关键页面与权限差异对比场景。

## 八、与正式实现（React + shadcn/ui）的对应关系

| 原型 | 正式实现 |
|---|---|
| `css/style.css` 的 `:root` 令牌 | Tailwind v4 主题变量 / CSS 变量 |
| `js/data.js` 的 Mock 数据 | `app/src/services/mock/` + 真实 API |
| `js/app.js` 的 `hasPerm()` | 新增 `getCurrentUserPermissions()` 服务 + 权限 Context |
| `[data-perm]` 属性隐藏按钮 | React 组件内 `hasPerm(code) && <Button/>` 条件渲染 |
| 菜单 `renderMenu()` 过滤 | `DashboardLayout.tsx` 侧边栏按权限过滤 |
| `403.html` | `AuthGuard` 的 `requiredPermission` 扩展 + 无权提示 |
| 权限矩阵 | 权限管理页新增矩阵视图组件 |

## 九、设计决策记录

1. **深海军蓝 + 曙光金**替代常见的企业蓝白配色，主题来自"辰光"品牌名，而非模板默认。
2. **权限矩阵作为母题**：RBAC 的本质是矩阵，把它做成视觉核心而非普通表格。
3. **身份切换器**：把"权限控制"从抽象概念变成可即时观察的体验，是原型对 V2 需求最强的表达。
4. **等宽字体承载权限码**：`user:create` 这类字符串本身就是代码，用等宽字体是内容驱动而非装饰。
5. **克制阴影、细边框**：企业后台需要密度与清晰，避免卡片堆叠的 SaaS 模板感。
