# 辰光 Agent 平台 — 项目启动说明书

> 适用：本地开发环境一键启动 / 手动启动。
> 目标：无需 Docker 即可跑通前后端，数据库用 SQLite，缓存用 fakeredis（内存实现）。

---

## 1. 概述

本项目前后端均可一键启动：

- 后端：FastAPI + SQLAlchemy 2.0（异步）+ SQLite + fakeredis
- 前端：React 19 + TypeScript + Vite
- 启动入口：项目根目录的 `start.bat`

启动脚本会自动完成：**创建/校验虚拟环境 → 安装后端依赖 → 准备数据库 → 安装前端依赖 → 启动前后端 → 等待就绪 → 打开浏览器**。

|------|----------|----------|

## 3. 快速启动（推荐）

直接双击项目根目录的 **`start.bat`**。

脚本按以下 5 个阶段执行：

| 阶段 | 动作 | 说明 |
|------|------|------|
| 1/5 | 检查 Python 环境 | 定位 `python` / `py -3`，首次运行创建 `.venv`；已存在则校验其可用性（失效时自动重建） |
| 2/5 | 检查后端依赖 | 校验 `fastapi/uvicorn/aiosqlite/fakeredis/alembic/sqlalchemy/minio` 等，缺失则 `pip install -r requirements.txt` |
| 3/5 | 准备数据库 | 运行 `bootstrap_db.py`（建表 + 灌演示数据 + 迁移升级） |
| 4/5 | 检查前端依赖 | 首次运行 `npm install`（`app/node_modules` 存在则跳过） |
| 5/5 | 启动服务 | 启动后端 8080、前端 5173（端口已占用则跳过），`wait_ready.py` 轮询就绪 |

**重复执行是安全的**：脚本会检测端口占用并跳过重复启动。

## 5. 手动启动

### 5.1 后端（项目根目录）

```bat
.venv\Scripts\python.exe -m uvicorn src.main:app --host 127.0.0.1 --port 8080
```

### 5.2 前端（`app` 目录）

```bat
npm.cmd run dev
```

> 注意：本机 PowerShell 执行策略禁用了 `npm.ps1`，必须用 **`npm.cmd`**，直接敲 `npm` 可能报错。

### 5.3 数据库引导（可选，`start.bat` 已自动执行）

```bat
.venv\Scripts\python.exe bootstrap_db.py
```

辅助脚本说明：

| 文件 | 作用 |
|------|------|
| `start.bat` | 一键启动入口 |
| `bootstrap_db.py` | 数据库引导：首次建库灌数据、迁移升级、异常时备份重建 |
| `init_data.py` | 建表 + 写入演示数据（幂等） |
| `wait_ready.py` | 轮询等待前后端就绪 |

## 6. 架构说明（为何无需 Docker）

| 组件 | 本地开发方案 | 关键位置 |
|------|--------------|----------|
| 数据库 | SQLite 文件库 `chenguang.db` | `src/core/config.py` 的 `DATABASE_URL` 固定返回 `sqlite+aiosqlite:///./chenguang.db` |
| 缓存 | fakeredis（内存实现，接口与 Redis 一致） | `src/infra/redis_cache.py` |
| 主键自增 | `BigInteger().with_variant(Integer, "sqlite")` 兼容 SQLite | `src/core/base_model.py` |
| 对象存储 | MinIO（可选，见下方降级说明） | `src/infra/minio_client.py` |

> `.env` 中的 MySQL/Redis 配置在本地开发路径下**不生效**（代码已硬切到 SQLite/fakeredis）。若需切回 MySQL，需改 `config.py` 的 `DATABASE_URL` 并还原 `redis_cache.py`。

## 7. 本次启动修复内容

本次启动过程中发现并修复了两个问题：

### 7.1 `start.bat`：增加虚拟环境失效检测

**问题**：`.venv` 是旧机器（`d:\飞思Agent平台\...`，Python 3.13）创建并随项目迁移而来，其 `pyvenv.cfg` 指向已不存在的 `C:\Users\admin\...\Python313\python.exe`。旧脚本仅检查 `.venv` 文件夹是否存在，误判为「已就绪」，导致后续 `pip install` 报 `did not find executable`。

**修复**：`else` 分支新增可用性校验——`"%PY%" -c "import sys"` 失败时，删除 `.venv` 并用当前 Python 重建。

### 7.2 `requirements.txt`：补充缺失的 `minio`

**问题**：`src/infra/minio_client.py` 导入 `minio`，但 `requirements.txt` 未包含该依赖，导致重建虚拟环境后 `ModuleNotFoundError: No module named 'minio'`。

**修复**：在 `requirements.txt` 补充 `minio==7.2.20`，并在 `start.bat` 的依赖检查导入列表中追加 `minio`。

## 8. 注意事项 / 常见问题

1. **`start.bat` 必须保存为 GBK 编码 + CRLF 换行**。
   脚本首行 `chcp 936` + `PYTHONIOENCODING=gbk`，若用编辑器改存为 UTF-8，CMD 在 `chcp 65001` 下读取会出现文件指针错乱，纯 LF 换行会拆断 `if`/`for` 复合语句。

2. **虚拟环境失效（迁移目录 / 重装系统 / 升级 Python）**：现在由 `start.bat` 自动检测并重建，无需手动干预。

3. **端口占用**：8080 / 5173 被占用时脚本自动跳过对应服务（假定已在运行）。

4. **MinIO 未启动（降级）**：后端启动时会尝试 `ensure_bucket_exists()`，MinIO 未运行只会在日志打印一条 ERROR（`[WinError 10061] 连接被拒绝`），**不影响启动**，仅文件上传功能不可用。需要完整功能时用 `docker compose -f docker/docker-compose.yaml up -d` 启动 MinIO。

5. **asyncmy 在 Python 3.14 需源码构建**：`requirements.txt` 中的 `asyncmy`（MySQL 驱动）在 3.14 上无预编译 wheel，首次安装会现场编译（本机已成功构建）。虽然本地 SQLite 路径不 import 它，但安装时需本机具备 MSVC 构建工具链；若安装失败可临时从 `requirements.txt` 移除 `asyncmy`（不影响 SQLite 运行）。

6. **前端 mock/真实接口切换**：`app/.env.local` 当前为 `VITE_USE_MOCK=false` + `VITE_API_BASE=http://localhost:8080/api/v1`，即前端走**真实后端**。改为 `true` 则使用 `app/src/services/mock/` 的 mock 数据。

7. **数据库损坏**：`bootstrap_db.py` 迁移失败时会把旧库备份为 `chenguang.db.bak_<时间戳>` 后重建，不会直接丢数据。

8. **停止服务**：直接关闭后端/前端对应的命令行窗口即可；或按端口结束进程：
   ```bat
   netstat -ano | findstr :8080
   taskkill /PID <pid> /F
   ```

---

## 9. 停止服务

- 关闭 `start.bat` 弹出的两个命令行窗口（后端 8080、前端 5173）。
- 或使用上文第 8 节第 8 条的 `taskkill` 方式按端口结束进程。
